# Política de idioma

ApiBlueprint separa deliberadamente el idioma del código del idioma del producto.

## Código e identificadores técnicos

Se escriben en **inglés**:

- namespaces, clases, métodos y variables;
- nombres de archivos y carpetas;
- claves estables del manifest;
- identificadores de capabilities y endpoints;
- nombres de tests y commits.

## Superficie visible del producto

Se escribe en **español**:

- landing y configurador;
- mensajes de validación y errores;
- respuestas HTTP orientadas al consumidor;
- títulos, resúmenes y descripciones de OpenAPI/Swagger;
- documentación pública y textos exportados para el usuario.

Los elementos normativos del protocolo conservan su forma estándar (`GET`, `POST`, códigos HTTP, media types y nombres técnicos de cabeceras).
